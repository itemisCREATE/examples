Completion Transitions

This example demonstrates completion transitions: transitions that carry neither a trigger nor a guard, and fire when the state they leave has completed. The interesting case is a state that owns a sub machine - it completes when the sub machine does, so the owner can wait for a piece of work to finish without any event being exchanged.

For more details, please also refer to the Transitions and Final state sections of the statechart language reference, and to Multi state machine modeling for sub machines.

Writing One

A completion transition is simply a transition with an empty specification. There is no keyword: what makes it a completion transition is the absence of a trigger and of a guard. The Working state of the worker machine is left by one.

When Does a State Complete?

It depends on what the state contains:

  • A simple state completes as soon as its entry behavior has run - a completion transition leaving it fires immediately.
  • A composite state completes once every one of its regions has reached a final state.
  • A state that owns sub machines completes once every sub machine it owns has completed. A sub machine has completed when each of its top level regions is in a final state.
  • A state that has both completes when both are true: its own regions are final and its sub machines have completed.

A sub machine that cannot complete at all - one whose regions contain no final state - is ignored rather than blocking the owner forever. The statechart editor reports that case as a warning.

The Example Model

job is the sub machine that does the work. It walks Prepare, Run and Verify, one step event at a time, and then reaches its final state. Counting the steps in stepsDone makes the progress visible.

worker owns it. start moves it from Idle into Working, which embeds the job with submachine task. Nothing leaves Working on an event: the transition to Done is the completion transition, and it fires on the step that takes the job into its final state - not on the two before it.

worker itself ends in a final state, so it is completable too. Were it owned by a third machine, that machine's state would complete when ack arrives here.

Simulating Completion

Simulate the worker machine and raise start, then task.step three times. The first two steps advance the job only; the third one completes it, and the worker leaves Working in the same run-to-completion step.
