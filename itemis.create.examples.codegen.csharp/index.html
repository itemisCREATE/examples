C# Code Generation

This example demonstrates how to generate C# code from a statechart. We will use a simple light switch example and focus on the generator model and on the small amount of application code a generated state machine needs around it.

For more details, please also refer to the C# code generator section of the user guide.

Generator Model

In order to generate code we need to specify which code generator to use and into which folder to generate. For this, we need to create a so-called generator model. To do so,

  • Select the models folder in the Project Explorer
  • Right-click and choose New -> Code generator model
  • Follow the wizard to select the C# code generator and the state machine for which you want to generate C# code

Naming.baseNamespace decides the namespace of the generated state machine class; the runtime interfaces go into Itemis.Create.Statemachines and Itemis.Create.Timer, which Naming.libraryNamespace can change. Press [CTRL]+[SPACE] in the generator model to get a list of available features.

What the generator produces

Generating writes into src-gen:

  • LightSwitch.cs – the state machine. Every interface scope of the statechart becomes a nested interface (IUser, ILight) with a property on the machine, so the application talks to statemachine.User and statemachine.Light.
  • Each in event becomes a Raise<Event>() method, each out event a C# event, and each variable a property.
  • IStatemachine.cs, IEventDrivenStatemachine.cs, ITimed.cs, ITimerService.cs – the runtime contracts.
  • VirtualTimer.cs – a virtual clock for tests, which is what the generated SCTUnit tests drive.

Providing a timer service

The statechart uses after 30 s, so it is a timed state machine and needs an ITimerService before Enter() is called. The generator deliberately ships no wall-clock implementation — what "real time" means belongs to the application — so this example contains a small one in src/TimerService.cs, built on System.Threading.Timer:

Two details are worth copying into your own code. A time event arrives on a timer thread while the console thread may be raising a user event, so every call into the state machine is serialized on one monitor. And because the runtime namespace ends in Timer, the plain name Timer resolves to that namespace rather than to System.Threading.Timer — hence the using SystemTimer = System.Threading.Timer; alias.

Building and running

The project carries a plain SDK-style .csproj that compiles both src and src-gen, so the generated code is part of the build without any further setup: 

dotnet build
dotnet run

Type On and Off to operate the light; leave it on for 30 seconds to watch the time event switch it off again.
