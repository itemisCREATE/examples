C# Code Generation for SCTUnit with NUnit

SCTUnit lets you write tests for a statechart in terms of the statechart: enter the machine, raise events, let virtual time pass, and assert which states are active and which events were raised. This example generates those tests as an NUnit fixture, with Moq standing in for the statechart's operations.

For more details, please also refer to The SCTUnit language and to the C# code generator section of the user guide.

Two generator models

One generates the state machine under test, the other the NUnit fixture. Both write into src-gen, so the test project compiles one folder:

Two settings are worth pointing out. The statechart's generator model switches OutEventAPI { getters = true } on, because the fixture asserts about out events by reading the machine's own <Event>Raised members — the machine clears those when a run cycle starts, which is what makes an assertion after proceed mean the right thing. And the test's generator model names both namespaces: its own in Naming, and the machine's in StatechartNaming, since the machine is produced by the other generator model.

What the generator produces

The fixture carries a [SetUp] that builds a fresh state machine, a VirtualTimer and a Mock per operation callback, one [Test] per @Test operation of the test class, and a private method per helper operation. Assertions about out events read the machine's own <Event>Raised members, exactly as the C, C++, Java and Python fixtures read theirs; proceed becomes a leap of the virtual timer, so no test ever waits for real time.
