DISCLAIMER: This example only works on UNIX based systems due to the nature of the Eclipse console

Debug and trace a C++ state machine with TDT

Target Debugging & Tracing (TDT) shows a state machine that runs in your application at model level: the application reports each execution step, and itemis CREATE shows the active states, the raised events and the variable values in the statechart diagram. While the application is connected, you can also raise events and change variables from the simulation view. Please refer to the TDT documentation for more information.

The Tic-Toc example application

The example state machine has two states, Idle and Playing. The input event toggle switches between them. Within Playing the state machine alternates between the states Tic and Toc and raises the out events tic and toc when entering them. The time between these state changes is defined by the variable delay.

The state machine runs within an interactive command line application, which reads commands from the standard input and writes to the standard output. It runs on the host machine. To use TDT in your own application, you can take this example as a template.

Building the application

The example project is an Eclipse CDT project for C++11; configure the compiler tool chain of your platform in the project properties. The state machine and its TDT tracer are generated into src-gen from the two generator models in model: tictoc_sm.sgen enables generic tracing for the state machine, tictoc_tdt.sgen generates the class TictocTracer with create::cpp::tdt. Both use the same options. With automatic build switched on this happens automatically, otherwise select Generate Code Artifacts from the context menu of both files.

The tracer registers itself with the state machine when it is created. Its outgoing messages are the observable getMessages(), and it is itself an observer of incoming stimuli. The trace channels are part of the example, in src/channels: FileWriter writes the messages to a trace file, UdpStream sends and receives them over UDP, and Logger prints them to the console. src/main.cpp shows how they are connected.

Running the application

Run the executable from Eclipse (Run As > Local C/C++ Application on the project) or from a terminal. Optionally pass the IP address and the port of itemis CREATE, by default 127.0.0.1 and 4444. You will see this output: 

Sending to 127.0.0.1:4444
Welcome to Tictoc! Press:
>t< to toggle tictoc idle state
>+< to increase tictoc delay
>-< to decrease tictoc delay
>l< to enable or disable log
>u< to disable or enable udp tracing
>h< for this help
... followed by ENTER.

send: %tictoc.foo.y,0
send: %tictoc.count,0
send: %tictoc.delay,1000
send: %tictoc.x,5
send: %tictoc.b,f
send: %tictoc@Enter,1
send: #0,tictoc@tev.0.Set
send: #0,tictoc.b,t
send: #0,tictoc.i,42.000000
send: #1,tictoc@StateEntered,main.Idle

The first block is the application's start-up output, with the commands it understands. The second block logs the TDT messages the state machine sends. Besides the console, the messages go to the UDP socket and to the file trace.tdt.

Debugging and tracing the state machine

Choose Run As > Target Debugging & Tracing (Beta) from the context menu of model/tictoc.sct. The execution is shown in the regular simulation view. By default, it replays the trace file trace.tdt in the root of the project.

To debug the running application instead, open Run As > Run Configurations…, select the configuration in the category Target Debugging & Tracing, and choose Read trace from UDP socket on the tab Statechart Trace, with port 4444. Start the TDT run configuration first, then start the application. While it is connected, you can raise toggle and change delay from the simulation view.
